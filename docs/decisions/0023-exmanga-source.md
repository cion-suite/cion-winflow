# 0023. ExManga как источник глав

## Контекст

Remanga помечает платные главы `locked`, а купить их внутри cion-reader нельзя.
ExManga — отдельный сервис с пулом платных глав Remanga: пользователи
загружают купленные главы, сервис отдаёт их со своего хоста. Нужен источник,
который закрывает эти главы, но **не делает запросов к серверу Remanga**:
учётка, контент и картинки должны приходить с ExManga.

Проверено на живом API и расширении `exmanga_4.3.0`:

- `dir` тайтла и числовой `id` главы у ExManga совпадают с Remanga
  (например, глава `2827338` — том 3, глава 936 у обоих);
- поиск и метаданные публичные: `GET /api/manga?name=&skip=&take=` и
  `GET /api/manga?dir=`;
- полный список глав публичный: `GET /api/manga/history?dir=` (id, том,
  номер, дата, просмотры);
- контент требует входа: `GET /api/chapter?id=&extra=true&history=true`
  с `Authorization: Bearer`; ридер расширения берёт из ответа `links` —
  подписанные ссылки `exmanga.org/storage/...?sign=&expires=`;
- вход — `POST /api/auth/login` с JSON `{ email, password }`, ответ
  `data` — JWT; проверка — `GET /api/auth`;
- расширение ставит одну сессию на сервис, поэтому учётка у нас хранится
  как обычная зашифрованная Bearer-учётка.

## Решение

Добавить адаптер `exmanga` в `server/src/sources/exmanga/`:

- `code = "exmanga"`, `default_base_url = "https://exmanga.org"`,
  `lang = "ru"`, capabilities: `Search`, `Chapters`, `Images`, `Volumes`,
  `AltNames`, `Auth`, `Login`, `SignedUrls`;
- `external_id` тайтла — `dir`; `external_id` главы — числовой `id`;
- `chapter_key` строится общим `sources/keys.rs` теми же томом/номером,
  поэтому ключи совпадают с Remanga и fallback/прогресс общие;
- `title()` — `/api/manga?dir=`, `search()` — `/api/manga?name=`,
  `chapters()` — `/api/manga/history?dir=`; эти запросы не отправляют
  Bearer, чтобы протухшая учётка не ломала поиск и импорт;
- `content()` без учётки сразу возвращает `AuthRequired`, с учёткой идёт
  в `/api/chapter`; `links` приоритетнее `pages` (формат Remanga);
- `login()` — email/пароль и JWT, `verify()` — `GET /api/auth`;
- `resolve_image`/`resolve_cover` разрешают только `exmanga.org`,
  `*.exmanga.org` и настроенные `image_hosts`; `reimg.org`,
  `remanga.org` и `api.remanga.org` отклоняются.

Адаптер регистрируется в `SourceKind`, реестре и списке дескрипторов
последним: Remanga остаётся приоритетнее для общих глав, а ExManga
закрывает те, что у Remanga `locked` (недоступный вариант уходит в конец
независимо от ранга).

## Следствия

- Без учётки ExManga главы импортируются и видны в списке, но открытие
  даёт 403 `source_auth_not_configured`; после входа глава помечается
  `chapters.auth_required = 1` и кэшируется в пространстве пользователя.
- Отклонённый/истёкший JWT даёт 502 `source_auth_invalid`. Автоматического
  refresh нет: `last_verified_at` истёк или `verify` вернул 401 — нужен
  повторный вход. Это осознанно: хранить refresh-пару ради одного сервиса
  пока не нужно.
- `chapters()` с пустым `history` возвращает `NotFound`: тайтл, которого
  нет в пуле, не привязывается пустой карточкой.
- Список ExManga может начинаться не с первой главы: это неполный пул,
  а не полный каталог. Отсутствующие главы по-прежнему берутся из Remanga.
- Подписанные ссылки страниц протухают; прокси уже умеет при 401/403/410
  до двух раз перезапрашивать список страниц — для ExManga это и есть
  обновление подписи.
- В настройках вкладка «Источники» переименована в «Авторизации»: теперь
  там две учётки (Remanga и ExManga), и название «Источники» путало с
  админским списком источников.
- `base_url`, `site_url` и `image_hosts`, указывающие на `remanga.org`
  или `reimg*.org`, отклоняются при сборке адаптера/конфига. Даже
  ошибочная настройка администратора не направит ExManga на Remanga.

## Альтернативы

- **Ходить в Remanga за списком глав/метаданными ExManga.** Отклонено:
  явное требование «ExManga никогда не обращается к серверу Remanga» и
  независимость от блокировок Remanga. ExManga сам отдаёт `dir`, id глав
  и метаданные.
- **Использовать облачный аккаунт расширения (email/пароль на его
  бэкенде) вместо аккаунта сайта.** Это один и тот же API ExManga;
  отдельной сущности не нужно.
- **Считать все главы из `history` доступными без входа.** Тогда
  знаменатель прогресса обещал бы больше, чем пользователь может открыть.
  Поэтому контент всегда требует учётку, а `auth_required` ставится после
  первого успешного открытия.
- **Проксировать картинки через `server.link` из ответа.** Не нужно:
  `links` уже содержат абсолютные подписанные URL на хосте ExManga, а
  allowlist не пропустит чужие.

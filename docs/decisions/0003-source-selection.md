# 0003. Выбор источника и fallback по главам

- **Статус:** принято
- **Дата:** 2026-11-24
- **План:** [../planned-now.md](../planned-now.md)
- **Связано:** [0002-source-abstraction.md](0002-source-abstraction.md)

## Контекст

У одного тайтла может быть несколько `source_entries`: например, Remanga, Mangamir и MangaLib. Нужно автоматически выбирать не «основной источник навсегда», а лучший доступный вариант:

- у каждого набора источников свой приоритет: для русской манги Remanga → Mangamir → MangaLib, для других языков — свой список;
- если один источник содержит больше глав, выигрывает он;
- при одинаковом количестве глав выигрывает более приоритетный;
- если конкретная глава в выбранном источнике платная, удалена или недоступна, она берётся из следующего источника;
- метаданные о полноте и доступности хранятся в БД, чтобы не опрашивать источники на каждый показ;
- прогресс чтения хранится в БД и не зависит от того, из какого источника открыта глава.

## Решение

1. **Приоритеты источников.** Таблица `source_priorities(kind, lang, source_id, rank)`: меньший `rank` — выше приоритет; `lang` — ISO 639-1 (`ru`, `en`), `lang = '*'` — запасной набор. Пример: `manga/ru` = Remanga → Mangamir → MangaLib, `manga/en` — свой список, `anime/ru` — свой. Приоритет — тай-брейкер, а не жёсткое назначение источника.

2. **Статистика источника у тайтла.** После импорта и каждого refresh в `source_entries` считаются `chapter_count` — число уникальных `chapter_key` без `removed_at` (не строк-вариантов, иначе несколько групп перевода раздувают полноту), `available_count` (у ключа есть хотя бы один доступный вариант; `unknown` считается доступным оптимистично), `locked_count`, `missing_count`, `stats_updated_at`. Это метаданные, по которым принимается решение без сетевых запросов.

3. **Предпочтительный источник тайтла.** Среди включённых `source_entries` выбирается запись с максимальным `chapter_count`; при равенстве — меньший `rank` в `source_priorities` для `(titles.kind, titles.lang)`; затем `is_primary`; затем `id`. Источник с `available_count = 0` не становится предпочтительным, пока есть источник с доступными главами; если доступных нет нигде, выбирается самый полный, а открытие вернёт `source_locked`. Результат хранится в `titles.preferred_source_id` и пересчитывается при импорте, refresh, включении/выключении источника и когда `available_count` падает до нуля. `titles.origin_source_id` хранит источник, из которого тайтл импортирован, — это разные вещи.

4. **Fallback на уровне главы.** Для канонического `chapter_key` сначала пробуется вариант из предпочтительного источника. Если его нет, он помечен как locked/missing или запрос не удался, выбирается следующий вариант: по доступности (`available` → `unknown` → `locked`/`missing`), затем по приоритету источника, `is_primary`, `ordinal_site`, `id`. Успешный ответ помечает главу `available` и заполняет `content_kind`/`page_count`; `Locked`/`NotFound` помечают `locked`/`missing`; временные ошибки (`RateLimited`, `Upstream`) не меняют доступность, но позволяют попробовать следующий источник. Если картинки уже полученной главы отдают `401/403/410` после перезапроса списка, глава тоже помечается `locked`, а клиент повторяет canonical `/content` и получает fallback.

5. **Метаданные доступности.** `chapters.availability` — `unknown | available | locked | missing`, `availability_checked_at`, `page_count`. `locked` доверяем ограниченное время (например, 6 часов), `missing` — 24 часа, после чего состояние снова `unknown`; фоновый refresh обновляет данные. Поэтому постоянных проверок нет: запрос к источнику происходит при открытии главы или фоновом обновлении, а не при каждом показе тайтла.

6. **Канонический маршрут чтения.** Основной эндпоинт — `GET /api/titles/{title_id}/chapters/{chapter_key}/content` (и `/text`): сервер сам выбирает вариант и при необходимости откатывается на другой источник. Прямой `GET /api/chapters/{id}/content` остаётся для конкретного варианта (админ/отладка) и fallback не делает.

7. **Прогресс — в БД и по ключу.** `progress` и `chapter_reads` живут в SQLite, ключ — `chapter_key`; API принимает `chapter_key`, а не `chapter_id`. Переключение источника и fallback не меняют прогресс.

8. **Один тайтл — один язык в первых фазах.** Приоритет выбирается по `titles.lang`; иноязычные версии — отдельные тайтлы. Смешивать русскую и английскую версии в одном тайтле будем только при явной необходимости.

9. **Несопоставленные ключи.** Если у источников разошлась нумерация и `chapter_key` не совпал, администратор связывает ключи через `chapter_aliases` (0002). Автоматических эвристик склейки нет; решение 0012 разрешает автоматике только предлагать связки-диапазоны, а применять их должен администратор.

10. **Ручное управление.** Приоритеты задаются списком на `(kind, lang)`; `is_primary` — тай-брейкер и признак для отображения, а не жёсткий override. Автоматически выбранный источник виден в метаданных тайтла; если он ошибочен, администратор меняет приоритеты или выключает источник.

## Примеры

| Remanga | MangaLib | Что выбирается |
|---|---|---|
| 10 глав | 10 глав | Remanga: количество равно, приоритет выше |
| 10 глав | 12 глав | MangaLib: глав больше |
| 10 глав, 2 locked | 10 глав | Remanga для доступных глав, MangaLib для двух locked |
| 10 глав, 2 locked | 12 глав | MangaLib как более полный; его locked-главы откатываются на Remanga |

## Последствия

- На странице тайтла видны источник, полнота и доступность — без сетевых запросов.
- Открытие главы делает запрос только к выбранному варианту; при неудаче — к следующему, с обновлением метаданных.
- Предпочтительный источник может измениться после refresh или падения источника; ссылки и прогресс остаются каноническими.
- `available_count` используется для отображения и проверки «есть ли вообще доступные главы», но не для ранжирования источников тайтла: иначе две locked-главы переключали бы весь тайтл, что противоречит требованию «locked-главы берутся из другого источника».

## Рассмотренные альтернативы

| Вариант | Почему отклонён |
|---|---|
| Один основной источник на весь тайтл навсегда | не учитывает, что в другом источнике глав больше или часть глав доступнее |
| Выбор только по приоритету, без учёта полноты | при равном приоритете теряются главы, которых нет в первом источнике |
| Выбор источника по `available_count` | при равном количестве глав две locked-главы переключали бы весь тайтл; нужен fallback только для этих глав |
| Опрашивать все источники при каждом открытии | медленно и создаёт лишнюю нагрузку; метаданные и ленивый fallback дешевле |
| Хранить прогресс по `chapter_id` источника | при смене источника прогресс теряется; ключ должен быть каноническим |
| Автоматически склеивать главы по эвристикам | ошибки нумерации хуже ручного alias; автоматика только для одинакового `chapter_key` |

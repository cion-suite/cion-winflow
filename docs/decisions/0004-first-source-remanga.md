# 0004. Первый источник — Remanga v2

- **Статус:** принято, реализовано в фазе 4
- **Дата:** 2026-11-25
- **План:** [../planned-now.md](../planned-now.md)
- **Связано:** [0002-source-abstraction.md](0002-source-abstraction.md), [0003-source-selection.md](0003-source-selection.md)

## Контекст

Фазе 4 нужен первый настоящий источник, чтобы пройти путь «поиск → импорт → главы → чтение главы → прогресс». Кандидаты различались формой: Remanga отдаёт JSON API, MangaLib и Mangamir — HTML с Cloudflare/JS-челленджами. План требует `probe` до написания адаптера и допускает HTML только при статической отдаче.

Проверка 2026-11-25:

- `api.remanga.org/api/v2/search/` отдаёт JSON без авторизации;
- `api/v2/titles/{dir}/` — метаданные и `branches`; без завершающего слэша — 301;
- `api/v2/titles/chapters/?branch_id={id}&page={n}` — главы по 30, `next` — номер страницы;
- `api/v2/titles/chapters/{id}/` — страницы (`pages: [[{link,width,height}]]`) и `content_type: "comics"`;
- картинки `imgN.reimg2.org` отдаются с `Cache-Control: immutable` и без Referer;
- платная глава возвращает 200 с `is_paid: true` и пустым `pages`, а не 403.

## Решение

1. **Первый адаптер — Remanga v2, `MediaKind::Manga`.** Все типы сайта (манга, манхва, маньхуа, комикс) — манга для каталога; аниме и книги сайт не отдаёт.
2. **`external_id` тайтла — `dir`** (`<13.10.2026>naruto_`), потому что `titles/{dir}/` — единственный работающий lookup; числовой id не фильтруется и по нему нет эндпоинта. `dir` URL-кодируется целиком, цифровой id сохраняется в `source_entries.raw_json` как запасной признак.
3. **`external_id` главы — числовой `id`**, контент — `titles/chapters/{id}/`. `volume` — `tome > 0`; `tome = 0` означает отсутствие тома.
4. **`chapters()` сначала читает title**, затем обходит перечисленные `branches[].id`. Неперечисленные ветки не импортируются: они могут относиться к другому тайтлу.
5. **Платные главы — `is_locked`.** `content()` при `is_paid = true` или пустом `pages` возвращает `SourceError::Locked`, а не пустую главу.
6. **`content_kind = Images` на импорте.** Сайт комиксовый, дескриптор объявляет `Images`; при расхождении `content()` вернёт 502 по общему правилу.
7. **Картинки — абсолютные immutable-ссылки.** `image_ref` и `image_url` — один и тот же URL; `resolve_image` проверяет `*.reimg.org`/`*.reimg2.org`/`remanga.org`. Подписанных URL у источника нет.
8. **Конфиг:** `site_url` (для обложек и ссылок), `image_hosts`, `language = "ru"`. `base_url` — только колонка `sources.base_url` и только API-хост.
9. **Тестовый шов — `fixture` под `cfg(debug_assertions)`.** Интеграционные тесты проходят весь путь через роутер с локальным HTTP-сервером картинок; release его не содержит. `SSRF_ALLOW_LOOPBACK` разрешает loopback только в тестах.

## Последствия

- Парсеры проверяются фикстурами (`sources/remanga/fixtures/`), сеть — тонкая обёртка; `contract_suite` держит дескриптор, уникальность и стабильность ключей.
- Импорт Naruto — 24 запроса по 30 глав; это осознанно синхронно, страницы грузятся лениво.
- `dir` может измениться; тогда потребуется ручной переимпорт или миграция по `raw_json.id` — это ограничение источника, а не контракта.
- Второй источник фазы 5 должен быть другой формы (HTML или иная нумерация), чтобы проверить абстракцию, а не повторить API-путь.

## Рассмотренные альтернативы

| Вариант | Почему отклонён |
|---|---|
| MangaLib/Mangamir сразу | HTML и Cloudflare/JS-челленджи; `probe` не гарантирует стабильность, а фаза 4 должна дойти до чтения |
| Начать с HTML-адаптера и `scraper` | нет статического HTML-источника с надёжной разметкой под рукой; API даёт чистые фикстуры и быстрый первый проход |
| Использовать числовой id тайтла | `titles/{id}` — 404, `?id=` — не фильтр |
| Считать `content_kind = NULL` | сайт комиксовый, формат известен; NULL заставил бы прогресс требовать предварительного `/content` без причины |
| Классифицировать любой 403 как Cloudflare | 403 бывает и у глав; для probe 403 отдаётся как `cloudflare`, а контент различает `Locked` по `is_paid` |

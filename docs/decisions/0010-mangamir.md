# 0010. Mangamir как третий источник

## Контекст

Remanga покрывает не все тайтлы, а RuMix — не все главы. Нужен ещё один
русскоязычный HTML-источник, который можно добавить без изменения схемы БД и
без спецкода в каталоге.

## Решение

Добавить адаптер `mangamir` в `server/src/sources/mangamir/`:

- `external_id` тайтла — slug из `/manga/<slug>`;
- `external_id` главы — `data-chapter-slug` (`tom-1-glava-0`);
- поиск — `GET /manga?q=<query>`, результаты и метаданные читаются из JSON-LD
  (`ItemList`, `ComicSeries`, `AggregateRating`), HTML используется как запасной
  вариант;
- главы — `li[data-chapter-slug]`, номер/том/название — из `title` ссылки.
  Свёрнутая страница отдаёт только первые и последние главы, поэтому адаптер
  находит Livewire-компонент `pages::book.show`, берёт `livewireScriptConfig`
  (`uri`, `csrf`) и `Set-Cookie` того же GET и делает
  `POST showAllChapters` — полный список приходит в `effects.islandFragments`;
- контент — все страницы уже в HTML (`img[src*="/pages/"]`), без отдельного API;
- картинки — `img.mangamir.com`, сайт — `mangamir.com`, оба в allowlist;
- UA обязан начинаться с `Mozilla/5.0`, иначе сайт отвечает заглушкой.

Тип приводится к `TitleKind` (`Manhwa`/`Manga`/`Manhua`, неизвестный — `Other`),
поэтому CHECK в `titles.kind` не ломается, даже если Remanga такого типа не
знает.

## Следствие для привязки

Ручная привязка источника в UI убрана. `discover/add` перед созданием тайтла
ищет существующий по точному нормализованному названию или альтернативному
названию и привязывает источник к нему. Если названия расходятся, создаётся
отдельная карточка — это осознанное ограничение, пользователь правит вручную.

## Следствие для приоритетов

Приоритет источника важнее полноты: главы, которые есть на более приоритетном
источнике, берутся с него, а менее приоритетный заполняет только пропуски.
Метаданные сливаются из всех привязанных источников в порядке приоритета:
первый непустой `description`/`status`/`year`/`rating`/`lang`, первый конкретный
`kind`, списки объединяются. Обложки добираются по размерам: preferred первым,
остальные источники — только пустые слоты; ручные размеры не перетираются.

## Альтернативы

- **Парсить только HTML.** JSON-LD устойчивее к редизайну, поэтому имя,
  описание, жанры и рейтинг читаются из него; главы, даты, тип, статус и год
  берутся из HTML — `hasPart` в JSON-LD на свёрнутой странице тоже неполный.
- **Отдельная схема для «несовместимых» типов.** Не нужна: `TitleKind` — общий
  словарь, адаптер обязан свести тип к нему.
- **Требовать полный набор обложек.** Не нужно: `SourceCovers` допускает
  отсутствующие размеры, сервер отдаёт ближайший сохранённый, а синхронизация
  добирает пропуски из других источников.

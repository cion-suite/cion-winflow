# 0009. Тип произведения принадлежит тайтлу

- **Статус:** принято
- **Дата:** 2026-11-26

## Контекст

Прежняя модель знала три значения `kind`: `manga`, `anime`, `book`. Они
использовались одновременно как тип тайтла, как тип источника и как ключ
приоритетов `(kind, lang)`:

- `titles.kind` — канонический тип;
- `source_entries.kind` — что вернул источник;
- `source_priorities.kind` — для какого типа задан приоритет;
- дескриптор источника объявлял `kinds` и `default_kind`.

Это смешивало разные сущности. Аниме и книги — не формат тайтла: они будут
подключаться к тайтлу как связанный контент (`content_kind = video` и
будущий текст). Пользователю нужны типы произведений в терминах источника,
например «Манхва», «Маньхуа», «Западный комикс».

## Решение

1. **Тип — свойство тайтла.** `titles.kind` принимает восемь значений,
   повторяющих фильтр типов Remanga:
   `manga`, `manhwa`, `manhua`, `western_comic`, `ru_comic`,
   `indonesian_comic`, `other`, `original`.
2. **Источник — провайдер контента, а не тип.** Дескриптор больше не
   объявляет `kinds`/`default_kind`; `source_entries` и `source_priorities`
   не хранят `kind`. Один `source_entry` — уникальная пара
   `(source_id, external_id)`.
3. **Тип берётся из метаданных источника.** Remanga отдаёт `type.name`,
   RuMix — тип в заголовке страницы. Неизвестный тип становится `other`.
   При привязке источника к существующему тайтлу тип не проверяется и не
   меняется.
4. **Приоритеты — по языку.** `source_priorities(lang, source_id, rank)`,
   `lang = '*'` — запасной набор. Источник не привязан к типу, поэтому
   отдельный набор для каждого типа не нужен.
5. **Админского импорта нет.** Импорт выполняют ленивое добавление из
   библиотеки (`POST /api/discover/add`) и привязка источника к тайтлу
   (`POST /api/titles/{id}/sources`). Отдельный экран импорта в `/admin`
   удалён.

## Последствия

- Миграция 0008 пересобирает `titles`, `source_entries` и
  `source_priorities`. Старые `anime`/`book` переносятся в `other`, чтобы не
  потерять библиотеку и прогресс. Для уже импортированных из Remanga тайтлов
  фактический тип восстанавливается из `source_entries.raw_json` (`type.name`),
  иначе все манхвы и маньхуа остались бы «Мангой». `db::run_migrations` выключает внешние
  ключи на соединении мигратора: SQLx для SQLite всегда оборачивает миграцию
  в транзакцию, где `PRAGMA foreign_keys` — no-op, а `DROP TABLE` родителя с
  `ON DELETE CASCADE` удалил бы дочерние строки. После миграции ключи
  включаются обратно, и выполняется `PRAGMA foreign_key_check`.
- Смена типа тайтла больше не блокируется привязанными источниками:
  источник не знает тип.
- Приоритеты задаются только для языка; админский экран потерял выбор типа.
- Старый код RuMix различал только «ранобэ/не ранобэ», поэтому уже
  импортированные RuMix-тайтлы могли сохраниться как `manga`, даже если это
  манхва или маньхуа. Тип такого тайтла можно поправить в форме вручную:
  HTML-источник не хранил исходный тип, автоматически восстановить его в
  миграции нельзя.
- `ChapterKind`/`ContentKind` не меняются: это свойства главы и контента,
  а не произведения.

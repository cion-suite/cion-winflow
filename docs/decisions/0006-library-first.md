## Контекст

Каталог показывал только уже импортированные тайтлы и требовал админского импорта до того, как читатель мог что-то открыть. Для закрытого агрегатора это лишний шаг: тайтл нужен тогда, когда пользователь его ищет. Сайдбар дублировал единственный основной экран, занимал место и мешал на телефоне.

## Решение

1. **Корневой экран — библиотека, сайдбара нет.** Ссылки живут в шапке и меню пользователя; экран каталога удалён. `GET /api/catalog` и его тесты остаются серверным API, но UI их не использует.
2. **Тайтл добавляется из поиска.** Диалог на библиотеке ищет по всем включённым источникам с `Search` и `Chapters` (`GET /api/discover/search`), выбор результата (`POST /api/discover/add`) импортирует тайтл, если `source_entry` ещё нет, и добавляет запись в библиотеку со статусом `planned`. Импорт доступен любому пользователю с сессией; маршрут `add` ограничен rate limit, потому что ходит в чужую сеть.
3. **Одна библиотека, а не каталог.** Статусы `planned|in_progress|completed|on_hold|dropped|not_interested`, `favorite` — отдельный флаг, не мешающий статусу. Своих закладок не больше трёх; закладка ссылается только на тайтлы из библиотеки. Поиск в шапке ищет только по своей библиотеке, сортировка — по обновлению, добавлению, названию или оценке.
4. **Недоступные главы скрыты.** Страница тайтла делится на вкладки «Главы» (первая) и «Главная». Список глав не показывает варианты без рабочего источника (`locked`/`missing`), сортируется по тому и номеру, фильтруется по названию. «Читать» продолжает с сохранённого прогресса или с первой доступной главы.
5. **Прочитанное — журнал, а не эвристика.** `PUT /api/progress/{title_id}` пишет `chapter_reads` по каноническому ключу; карточка библиотеки показывает `read_count/chapter_count`, страница тайтла — отметку главы.
6. **Ручное создание — в админке.** Форма `POST /api/titles` перенесена в `/admin` как временный путь для тайтлов без источника; после создания админ переходит на карточку.

## Последствия

- Поиск и добавление работают только по источникам, которые администратор завёл и включил.
- Первый пользователь, добавивший тайтл, платит временем импорта; остальные получают уже готовую запись и библиотеку без сети.
- Обложка из выдачи источника (`GET /api/sources/{code}/cover?ref=`) доступна любой сессии: она нужна диалогу добавления, а не только админке.
- `library` пересобрана миграцией 0004 (`not_interested`, `favorite`); `library_tabs` и `library_tab_items` удаляются вместе с записью библиотеки через составной FK.
- Каталог может вернуться как отдельный админский экран, но не как обязательный шаг перед чтением.

## Рассмотренные альтернативы

| Вариант | Почему отклонён |
|---|---|
| Оставить каталог обязательным шагом | Лишний экран: пользователь всё равно ищет по источникам, а не листает каталог |
| Импортировать тайтл только при открытии карточки | Карточка появляется только после импорта; без импорта её не открыть, поэтому добавление и открытие совмещены |
| «Любимое» как статус | Нельзя одновременно «Читаю» и «Любимое»; флаг проще и не ломает фильтры |
| Неограниченные свои закладки | Интерфейс вкладок рассчитан на несколько штук; три — сознательный лимит первого этапа |
| Оставить поиск по источникам только админу | Противоречит цели: круг читателей сам добавляет себе тайтлы |

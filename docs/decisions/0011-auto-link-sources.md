# 0011. Автопривязка источников при добавлении тайтла

## Контекст

Тайтл часто есть сразу на нескольких источниках: Remanga и Mangamir отдают
одно произведение, но главы у них разной полноты (платные главы Remanga,
новые главы Mangamir). Сейчас пользователь добавлял тайтл с одного источника,
а копии с остальных привязывал вручную: искал тот же тайтл в диалоге и жал
«Добавить» ещё раз. При росте числа источников это превращается в двойную
работу для каждого тайтла.

## Решение

1. **Поиск в диалоге дедуплицируется.** `GET /api/discover/search` сортирует
   выдачу по приоритету источника (`source_priorities` для языка источника,
   затем код) и оставляет один результат на нормализованное название —
   карточку самого приоритетного источника. Например, если тайтл есть на
   Remanga и Mangamir, в выдаче остаётся Remanga.
2. **Добавление привязывает копии автоматически.** После импорта
   `POST /api/discover/add` вызывает `auto_link_sources`: для каждого
   остального включённого источника того же языка он ищет тайтл и, если
   нашёл, импортирует его к той же карточке (`source_admin::import` с явным
   `title_id`). Новая карточка не создаётся.
3. **Сначала основное название, потом альтернативные.** Первый проход ищет
   по основному названию и требует точного совпадения нормализованного
   названия результата. Если источник ничего не вернул, второй проход
   пробует альтернативные названия (не больше пяти запросов на источник) и
   принимает совпадение основного или альтернативного имени кандидата с
   набором названий тайтла.
4. **Только тот же язык.** Источники с другим `lang`, чем у тайтла, не
   участвуют, чтобы английская копия не подмешивалась к русской карточке.
5. **Best effort.** Ошибка поиска или импорта одного источника логируется и
   не отменяет добавление. Уже привязанные источники пропускаются.

## Следствия

- Добавление одного тайтла может занять больше времени: один поиск на
  источник, плюс полный импорт найденных. `add` уже под rate limit и ходит в
  чужую сеть, поэтому это осознанная цена.
- Существующие тайтлы не перепривязываются автоматически: автопривязка
  работает при добавлении. Повторное добавление того же тайтла запускает её
  ещё раз и добирает недостающие источники.
- Совпадение остаётся точным после нормализации (регистр и пробелы).
  Сомнительные случаи пользователь правит вручную; ручной привязки в UI нет.

## Поправка (0019)

Пункт 3 дополняется: тот же поиск выполняется и при открытии страницы тайтла
(`source_discovery`), но не как безлимитный фон, а лениво и per-user — с
кэшем результатов в `title_source_checks`, бюджетом источников и общей
блокировкой на тайтл. См. [0019](0019-source-discovery-on-open.md).

## Альтернативы

- **Автопривязка при каждой синхронизации.** Отклонено: синк и так ходит во
  все привязанные источники, а поиск по всем включённым источникам на каждое
  открытие тайтла умножает запросы и может подмешать чужой тайтл. Поправка
  0019 разрешает ленивый поиск при открытии с кэшем и лимитами.
- **Нечеткое сравнение названий.** Отклонено: при малом числе источников
  цена ошибки (чужие главы в карточке) выше пользы. Начинаем со строгого
  равенства, при необходимости добавляем ручные `chapter_aliases`.
- **Показывать в поиске все источники.** Отклонено: пользователь всё равно
  выбирает самый приоритетный, а дубли в выдаче мешают.

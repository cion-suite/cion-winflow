# cion-reader

Приватный self-hosted агрегатор манги, аниме и книг: каталог, библиотека и прогресс в одном месте для себя и небольшого круга читателей. React SPA + сервер на Rust (axum).

У проекта две цели:

1. **Продукт** — cion-reader для закрытого круга: авторизация, несколько источников, ридер и плеер.
2. **Обучение** — владелец проекта изучает Rust на практике.

Целевая платформа — веб-сервер (Linux); локальная разработка — Windows.

## Текущее состояние

Фазы 0–5 плана выполнены: `server/` на axum отдаёт API и статику `dist/`, работает SQLite (sqlx, миграции при старте), вход по инвайту, сессии в HttpOnly-cookie и защищённые экраны. Корневой экран — библиотека без сайдбара: вкладки статусов (включая «Любимое»), до трёх своих закладок, сортировка, поиск по своей библиотеке в шапке. Тайтл добавляется лениво: диалог ищет по всем источникам, `POST /api/discover/add` импортирует тайтл (если его нет на сервере) и сразу кладёт в библиотеку. Страница тайтла делится на вкладки «Главы» (первая), «О тайтле» и «Настройки» (только админ: связки-диапазоны глав с редактором и поиском расхождений); недоступные главы скрыты, прогресс и прочитанное видны. Администратор создаёт тайтлы вручную в `/admin`. Подключены три источника: Remanga v2 (JSON API), RuMix (HTML) и Mangamir (HTML): поиск, ленивый импорт, приоритеты по языку, preferred source, fallback по главам, связки-диапазоны (`chapter_alias_ranges`) и производные `chapter_aliases`, выдача контента, прокси картинок с дисковым кэшем и `ETag`, ридер с окном страниц и сохранением прогресса. При открытии страницы тайтла сервер в фоне обновляет главы и общие метаданные из источников по приоритету. Тип произведения — свойство тайтла (список типов Remanga), а не источника. У пользователя есть профиль, публичный внутри инсталляции: `/profile` — свой, `/profile/:id` — по uid; ник, аватар, статистика (прочитано глав, счётчики библиотеки), та же библиотека карточками без «Не интересно». Аватар загружается на своём профиле. Следующая фаза — видео.

- Целевая архитектура, фазы и критерии готовности — [docs/planned-now.md](docs/planned-now.md).
- Причины выбора и альтернативы — [docs/decisions/](docs/decisions/) (0001 архитектура, 0004 Remanga, 0005 RuMix, 0009 типы тайтлов, 0010 Mangamir, 0011 автопривязка источников, 0012 связки-диапазоны, 0013 язык просмотра, 0014 профили).

## Режим обучения

- Когда в коде появляется новая для проекта концепция Rust (владение, заимствование, времена жизни, `Result`/`?`, трейты, `async`), коротко объясняй её на примере этого кода.
- Ошибки компилятора разбирай по сути: что он проверяет и почему код не прошёл. Не обходи их через `clone()`, `unwrap()` или `unsafe` без объяснения.
- На вопрос «как сделать» — объясни и покажи подход. На просьбу «сделай» — сделай и кратко поясни неочевидные решения.
- Предпочитай простой идиоматичный код продвинутым приёмам, если они не нужны для задачи.

## Команды

Запускать из корня репозитория. Cargo-команды идут через `.claude/scripts/run-cargo.mjs`: он сам подставляет `--manifest-path server/Cargo.toml` и на Windows окружение Visual Studio.

```powershell
pnpm install                                 # зависимости фронтенда
pnpm dev                                     # Vite :1420 с прокси /api -> :3000
pnpm dev:server                              # axum на 127.0.0.1:3000
pnpm build                                   # проверка типов (tsc) и сборка фронтенда
pnpm lint                                    # ESLint, в том числе границы слоёв
pnpm exec shadcn add <компонент>             # добавить компонент shadcn

pnpm test                                    # cargo test (server)
pnpm check:rust                              # fmt --check + clippy -D warnings
```

Перед завершением задачи с Rust-кодом прогоняй `test`, `fmt --check` и `clippy`, с фронтендом — `pnpm lint` и `pnpm build`.

## Фронтенд

Раскладка и правила импортов — в `docs/architecture.md`. Кто кого может импортировать — таблица там же, это проверяет `pnpm lint`.

- Все экраны лежат в `src/pages/<имя>/`. Экран импортируется только из роутера `src/app/AppRouter.tsx`.
- `fetch` есть только в `src/api/client.ts`; там же `request<T>`, `apiUrl` и `ApiError`. `src/api` импортируют `pages`, `shell` и `app`, но не `ui`.
- Путь для `request` задаётся относительно префикса API: `request("/health")` -> `/api/health`. Ошибки сервера — `{ code, message }`; сетевой сбой — `ApiError` со `status: 0`.
- Снаружи `src/api` импортируется только через `@/api` (хуки, `AuthProvider`) и `@/api/client` (`request`, `ApiError`) — это проверяет `eslint-plugin-boundaries`.
- Авторизация: `useAuth()` даёт `user`, `isLoading`, `error`; защищённые экраны обёрнуты в `<RequireAuth>` в `AppRouter`, гость уходит на `/login`. 401 от запросов чистит кэш React Query и возвращает на вход. `/login` и `/register` живут вне `Layout`.
- Параметрические маршруты: `/title/:id` и `/profile/:id` — в `Layout`; `/reader/:titleId/:chapterKey` и `/watch/:titleId/:chapterKey` — вне `Layout`, во весь экран, но под `RequireAuth`. Корневой `/` — библиотека, `/library` редиректит на неё. Ссылки собирай через `src/lib/routes.ts`, чтобы `chapterKey` кодировался.
- Библиотека — единственный основной экран: вкладки (встроенные статусы, включая «Любимое», и свои закладки-статусы), сортировка (`sort` + `order`), карточки с прогрессом `read_count/chapter_count` и оценкой пользователя. Список — `useLibraryQuery` (`q`, `status`, `tabId`, `sort`, `order`); встроенные счётчики приходят в `counts.statuses`, счётчики своих закладок — в `LibraryTab.count`. Своих закладок не больше трёх; название уникально у пользователя; у тайтла один статус — встроенный или своя закладка.
- Добавление тайтла — диалог на библиотеке: `useDiscoverSearchQuery` ищет по всем включённым источникам, `useAddDiscoveredTitleMutation` импортирует тайтл при необходимости и добавляет его в библиотеку, после успеха открывается `/title/:id`. Выдача дедуплицируется по нормализованному названию: один тайтл — одна карточка от самого приоритетного источника. После добавления сервер сам привязывает копии с остальных включённых источников того же языка: сначала по основному названию, если ничего не нашлось — по альтернативным (не больше пяти запросов на источник). Тип импортированного тайтла берётся из метаданных источника. Обложки выдачи — `sourceCoverUrl`, через серверный прокси, а не напрямую с источника.
- Поиск в шапке (`LibrarySearch`) — `useLibraryQuery` с `q` и малым `page_size`; ищет только по своей библиотеке.
- Профиль (`pages/profile/`): `/profile` — свой (uid из `useAuth`), `/profile/:id` — чужой, оба в `Layout`; ссылка — `nav.profile` в `MENU_NAV`. `useProfileQuery` берёт `GET /api/users/{id}/profile` (`status`, `page`, `page_size`) и показывает ник, роль, дату регистрации и три счётчика (`stats.read_chapters`, `stats.counts.all`, `counts.statuses.completed`); ниже — вкладки статусов и те же карточки, что в библиотеке (`ui/LibraryCard`). Выбор вкладки/страницы привязан к uid и сбрасывается при переходе. «Не интересно» в чужую библиотеку не попадает, свои закладки её не фильтруют. Свой аватар меняется кнопкой-камерой (`POST /api/me/avatar`, multipart `file`) и удаляется (`DELETE /api/me/avatar`); `userAvatarUrl(id, avatar_updated_at, avatar_version)` показывается в шапке (вместо имени — только аватар, он открывает меню аккаунта, пункт «Профиль» ведёт на `/profile`) и в меню читалки; после мутаций инвалидируются `me` и `profile`.
- Читалка ходит только в canonical `/content` (никогда в `/api/chapters/{id}/content`), картинки берёт через `pageImageUrl` (`/api/pages/{id}/image`), прогресс — через `useProgressQuery`/`useSaveProgressMutation`; flush при закрытии вкладки — `requestKeepalive` (PUT, не `sendBeacon`). Смена главы пересоздаёт состояние через `key`. Прогресс восстанавливай по каноническому `content.chapter_key`, а не по ключу из URL.
- Верхняя панель читалки: слева стрелка и название тайтла одной ссылкой (логотипа нет), по центру номер главы `том-номер` со стрелками переходов, справа выбор статуса (встроенные и свои закладки одним списком) и меню пользователя. На телефоне названия и закладок в шапке нет: справа аватар, а страница, настройки и закладки — в нижней панели. Клик по странице переключает панели, прокрутка вниз прячет их после небольшого хода; скролл вверх состояние не меняет. На телефоне — все панели. Ширина колонки — настройка `readerWidth` (`sm`…`6xl`, `full`), в настройках выбирается Slider по шагам; настройки открываются Sheet справа / шторкой снизу, закладки — быстрый выбор статуса, включая свои закладки. Высоты страниц считаются по фактическим пропорциям картинки: широкие масштабируются до колонки, узкие показываются в натуральную ширину, поэтому кадры разного размера не дают вертикальных пробелов. Выше и ниже текущей монтируется небольшое окно страниц, префетч идёт по одной странице за окном; после смены ширины страница сохраняется.
- Страница тайтла: вкладки «Главы» (первая), «О тайтле» и «Настройки» (только админ). В списке скрывай главы, у которых нет рабочего варианта (`locked`/`missing`), сортируй по тому/номеру, фильтруй по названию; отметка прочитанного — по `read_keys`. На «О тайтле» — описание и метаданные (у админа ещё форма правки); в «Настройках» — только связки глав выбранного языка: одна строка на диапазон (слева связанная глава, справа каноническая, под иконкой связи — «Связано N», а «ожидают N» только когда их больше нуля; иконка связи открывает редактор с выбором канонической стороны и предпросмотром, корзина удаляет), правая колонка пустая, но занимает место, чтобы ширина не менялась, кнопки «Найти расхождения» (автопредложения по сериям глав с одинаковым номером и устойчивым сдвигом тома; односторонние пропуски — замечания) и «Добавить связку» (две поисковые главы); оставшиеся одиночные ручные пары — в сворачиваемом блоке «Точечные связи». После связки том/номер в списке берутся у канонической главы, а читается всё равно вариант выше по приоритету. Кнопка под обложкой: «Читать» — с первой главы, «Продолжить» — прогресс дальше первой, «Прочитано» — прогресс на последней главе **и** последняя или предпоследняя страница (`page >= page_count - 2`); в этом состоянии кнопка disabled, а не ссылка. Справа от глав (на широком экране) — рейтинг и информативные карточки «Источники»: иконка, название, число глав; без ссылок и кнопок. Статус библиотеки (включая «Любимое») — Select под обложкой на месте прежней кнопки «Любимое»; оценка пользователя — `score`, рейтинг источника — `title.rating`. Глаз у главы — кнопка: прочитанная глава приглушает карточку и показывает перечёркнутый глаз; если у главы есть непрочитанные предыдущие, глаз предлагает «Только эта глава» или «Эта глава и все предыдущие».
- Язык просмотра тайтла: если у тайтла есть включённые источники двух и более языков (`sources[].lang`), под названием — пилюля-переключатель (`Tabs variant="default"`); текста «Доступно глав: N» больше нет. Выбор хранится в URL `?lang=` и в `localStorage` (`titleLangs` по id), сервер фильтрует главы, выбранный вариант, карточку «Источники» и связки; читалка и переходы несут `lang`, `content` выбирает вариант только этого языка. Язык метаданных (`titles.lang`) не меняется. Сейчас все адаптеры `lang=ru` (MangaMir тоже), поэтому переключатель скрыт.
- Админка: `/admin` — две колонки источников («Русские»/«Англоязычные»), в каждой порядок = приоритет: стрелки, иконка, домен, гаечный ключ (popover с `base_url`, сбросом и probe) и Switch. Перестановка сохраняется сразу через `PUT /api/admin/source-priorities`; ссылки захардкожены в серверных дескрипторах (`default_base_url`), поэтому «настроить» источник = включить его. Ручное создание тайтла остаётся. Импорта из источника в админке нет: тайтлы добавляются через библиотеку. Пункт меню скрыт для не-админа, но сервер всё равно требует роль. На странице тайтла вкладка «Настройки» — связки глав; порядок источников задаётся здесь же в `/admin`, `AdminSourcePanel` удалён вместе с привязкой источников из UI.
- `GET /api/titles/{id}?lang=` отдаёт `aliases`, `read_keys`, `published_at`, `source_enabled` и собственные `volume`/`number_text`/`number_milli`/`chapter_kind` у вариантов, `priority_rank` и `lang` у источников, `title.cover_sizes` и `title.manual_cover_sizes`, `library.{status,score,custom_tab_id}`, `view_lang` (каким языком реально отфильтрованы главы; `null` — фильтра нет); у варианта главы есть собственный `chapter_key` (может отличаться от canonical). Выбранный вариант — первый доступный, а не свежий locked preferred. `lang` фильтрует главы по языку источника-варианта и ранжирует по приоритетам этого языка; язык, которого нет среди **включённых** привязанных источников, игнорируется. После attach/detach/primary/alias/alias-ranges/refresh инвалидируй `title`, `library`, `library-tabs`, `alias-ranges`, `chapter-content` и `progress` тайтла.
- Обложки: `titleCoverUrl(title, size)`, где `low` — выдача поиска и диалог добавления (у источников это `cover_ref` из выдачи, через `sourceCoverUrl`), `mid` — карточки библиотеки, `high` — страница тайтла. Админский `CoverEditorDialog` на странице тайтла загружает и удаляет каждый размер отдельно; занятые слоты — `title.cover_sizes`, отсутствующий размер сервер отдаёт из ближайшего. Кнопка «Получить из источника» (`useFetchSourceCoversMutation`) заново скачивает обложки привязанных источников; если есть ручные размеры (`title.manual_cover_sizes`), сначала спрашивает, заменять ли их.
- Компоненты shadcn не ставятся как библиотека: их код копируется в `src/ui/shadcn/` и принадлежит проекту. Перед написанием своего компонента проверь, нет ли готового в shadcn.
- Цвета бери из токенов темы (`bg-primary`, `text-muted-foreground`), а не задавай вручную: так работает смена темы.
- Алиас `@/` задан в трёх местах: `paths` в `tsconfig.json`, `resolve.alias` в `vite.config.ts` и `aliases` в `components.json`. Меняй их вместе, иначе `shadcn add` без ошибки создаст файлы не в той папке.
- `tsconfig.json` один, `baseUrl` не нужен: в TypeScript 6 он устарел. Документация shadcn для Vite описывает другую схему (`tsconfig.app.json`, `baseUrl`), её не применяй.
- Вызов бэкенда может завершиться ошибкой, всегда показывай её. Транспорт отдаёт `ApiError`, текст берётся из `error.message`; для известных кодов используй `useErrorText` (`api/errors.ts`), он переводит их через `lib/apiErrors.ts`.
- Библиотека и закладки ходят через `api.library`, поиск/добавление — через `api.discover`, тайтл — через `api.catalog`, связки глав — через `api.aliasRanges`; строковые статусы и типы (`manga|manhwa|manhua|western_comic|ru_comic|indonesian_comic|other|original`, статусы тайтла и библиотеки) — константы в `lib/catalog.ts`, не дублируй их литералами.
- Строки интерфейса не пиши в компонентах: добавляй ключи в `lib/i18n/locales/en.ts` и `ru.ts` и бери их через `useT()`. Настройки читай через `useSetting()`, пиши через `settings.set()`; прямой `localStorage` — только в `lib/settings.ts`, `shell/navbar/ThemeToggle.tsx` и `public/theme.js`.
- Сайдбара нет. Шапка — логотип со ссылкой на `/`, поиск и меню пользователя; его пункты задаёт таблица `lib/nav.ts` (`MENU_NAV`). Статические экраны и параметрические маршруты (`/title/:id`, `/reader/:titleId/:chapterKey`, `/watch/:titleId/:chapterKey`) перечислены списками `PAGES`/`PARAM_ROUTES` в `AppRouter`.
- `Button` из Base UI без `type` рендерится как `type="button"` и форму не отправляет: кнопке отправки нужен явный `type="submit"`.
- У `Button` вместо `asChild` проп `render`. Если он рендерит не `<button>`, добавь `nativeButton={false}`. Ссылку так не делай: она получит `role="button"`. Стилизуй её напрямую: `<a className={buttonVariants()} href="...">`.

## Сервер

- HTTP-обработчики тонкие, логика — в сервисах и репозиториях. Ошибки API — в формате `{ code, message }` (`server/src/error.rs`, `AppError` -> `IntoResponse`). Для JSON/Query/Path бери `ApiJson`/`ApiQuery`/`ApiPath` из `extract.rs`: стандартные экстракторы axum отвечают plain text.
- Неизвестный `/api/*` без сессии — JSON 401, с сессией — JSON 404; отсутствующий `/assets/*` — 404. `index.html` получают только навигационные запросы (`Sec-Fetch-Mode: navigate` или `Accept: text/html`). `GET /api/titles/{id}` и прочие пути с точками в идентификаторах работают.
- Публичные API-пути перечислены явно в `auth/middleware.rs` (`/api/health`, `/api/auth/*`); остальное под `/api` требует сессию. Мутации проверяют `Origin` и `Sec-Fetch-Site`; браузерная cookie `sid` — `HttpOnly`, `SameSite=Lax`, `Secure` по `COOKIE_SECURE`.
- Пароли — Argon2id в `spawn_blocking` с семафором; в БД только хеш. Сессия — 32 случайных байта, в БД SHA-256; idle 30 дней, абсолютный срок 90. Вход ограничен по IP (`tower_governor`) и по username (счётчик в памяти).
- Каталог: `GET /api/catalog` (поиск по `titles.name_lower` — Unicode-копия названия, `%`/`_` экранируются; фильтр `kind`, пагинация) остаётся серверным API, но своего экрана в UI больше нет. `GET /api/titles/{id}` -> `{ title, library, chapters, sources, aliases, read_keys }`; `POST /api/titles`, `PUT /api/titles/{id}`, `POST /api/titles/{id}/cover` — admin. Ручное создание тайтла живёт в `/admin`.
- Библиотека: `GET /api/library?q=&status=&tab_id=&sort=&order=&page=&page_size=` (`{ items, total, page, page_size, counts }`), `PUT/DELETE /api/library/{title_id}` для текущего пользователя. `PUT` принимает `{ status, score, custom_tab_id }`: `custom_tab_id` — своя закладка вместо встроенного статуса, `null` — встроенный. Поля записи: `status`, `score`, `custom_tab_id`, `read_count`, `chapter_count`. Встроенные статусы — `in_progress|planned|favorite|completed|dropped|on_hold|not_interested`; «Любимое» — такой же статус, отдельного флага нет. `status` в фильтре и `counts.statuses` учитывают только записи без `custom_tab_id`; `tab_id` фильтрует по своему статусу. `sort` — `updated|added|title|chapters|rating`, `order` — `asc|desc` (без `order`: `title` по возрастанию, остальные по убыванию). `updated` — дата последней опубликованной главы, `rating` — оценка источника. Пагинация общая — `pagination::resolve`.
- Профиль и аватары: `GET /api/users/{id}/profile?status=&sort=&order=&page=&page_size=` отдаёт `{ user, stats, library }` любой сессии внутри инсталляции. `user` — `{ id, username, role, created_at, avatar_updated_at }` (без пароля и сессий); `stats.read_chapters` считается по `chapter_reads`, `stats.counts` — счётчики библиотеки; `library` — та же выдача, что у `/api/library`, через `LibraryVisibility::Public`: `not_interested` скрыт и в счётчиках, и в списке, `tab_id` игнорируется, записи своих закладок считаются под встроенным статусом (иначе счётчики вкладок не сходились бы со списком), а `custom_tab_id` в публичной выдаче — `null`. Неизвестный/отключённый uid — 404 `user_not_found`. `POST/DELETE /api/me/avatar`: multipart `file` до 5 МиБ, JPEG/PNG/WebP/GIF, `resize_to_fill` 512×512 WebP в `DATA_DIR/avatars/{user_id}.webp` (атомарная запись tmp + rename под per-user `avatar_lock`, как `cover_lock` у обложек), `users.avatar_updated_at` — признак наличия, `users.avatar_version` — монотонный cache-buster (удаление его не сбрасывает). `GET /api/users/{id}/avatar` отдаёт `image/webp` с `ETag` по версии, `Cache-Control: private`, `nosniff`; нет аватара/файла — 404 `avatar_not_found`. `/api/me` и логин/регистрация отдают `avatar_updated_at` и `avatar_version` в `user`. Тело загрузки — `DefaultBodyLimit::max(6 МиБ)` на маршруте.
- Свои закладки-статусы: `GET/POST /api/library/tabs`, `PUT/DELETE /api/library/tabs/{id}`. Не больше трёх у пользователя, имя уникально. У тайтла ровно один статус: своя закладка перекрывает встроенный `status`; удаление закладки (`ON DELETE SET NULL`) возвращает сохранённый встроенный статус. Мультивыбора и `library_tab_items` больше нет (0007).
- Поиск по источникам для пользователя: `GET /api/discover/search?q=` (включённые источники с `Search` и `Chapters`, ошибки в `errors`). Выдача сортируется по приоритету источника (rank для языка источника, затем код) и дедуплицируется по нормализованному названию — на тайтл остаётся результат самого приоритетного источника (например, Remanga, а не Mangamir). `POST /api/discover/add` (`{ code, external_id }`): импортирует тайтл тем же кодом, что привязка источника, если `source_entry` ещё нет, и добавляет запись в библиотеку со статусом `planned`; у уже импортированного тайтла без обложек добирает их из источника. Если тайтл с таким же нормализованным названием или альтернативным названием уже есть, источник привязывается к нему, а не создаёт дубль (ручной привязки в UI больше нет). После этого `auto_link_sources` ищет тот же тайтл на остальных включённых источниках того же языка и импортирует найденное: сначала по основному названию (строгое совпадение), затем по альтернативным (до пяти запросов); ошибки источников логируются и не отменяют добавление. Роль admin не нужна; `add` под отдельным rate limit. Обложка выдачи `GET /api/sources/{code}/cover?ref=` доступна любому пользователю с сессией.
- Обложки: `title_covers` хранит до трёх размеров — `low` (поиск и диалог добавления), `mid` (карточки библиотеки), `high` (страница тайтла). `POST/DELETE /api/titles/{id}/cover?size=low|mid|high`: multipart `file` до 5 МиБ, JPEG/PNG/WebP/GIF, `image::Limits` в `spawn_blocking` с семафором, WebP в `DATA_DIR/covers/{id}/{size}.webp`, атомарная запись tmp + rename. `GET` отдаёт `ETag`, `Cache-Control: private` и при отсутствии размера — ближайший сохранённый (сначала более крупный, затем мелкий); UI добавляет `v={updated_at}`. При импорте и привязке источника обложки адаптера (`SourceCovers` low/mid/high) скачиваются автоматически, но только в пустые размеры — ручную не перетирают; сбой загрузки не отменяет импорт. Явная admin-операция `POST /api/titles/{id}/cover/from-source` (`{ replace_manual? }`) перебирает привязанные источники в порядке preferred → primary → привязка и обновляет source-размеры, а ручные (`source_id IS NULL`, включая строки 0005) — только с `replace_manual=true` (запись без файла на диске лечится всегда); ответ `{ sources, imported, skipped_manual, errors }`, ошибки одного источника не отменяют остальные. `GET /api/titles/{id}` отдаёт `title.cover_sizes` и `title.manual_cover_sizes`.
- Источники: дескриптор — данные (`sources/descriptor.rs`: `code`, `name`, `site_url`, `default_base_url`, `lang`, capabilities, config), dispatch — `enum SourceKind`, реестр собирается из таблицы `sources` в `AppState.sources` (`Arc<RwLock<SourceRegistry>>`) и пересобирается после `PUT`; guard не держится через `.await`. `SourceRegistry::load` добавляет недостающие строки `sources` с `base_url = NULL` (включение — ручное), чтобы приоритеты видели все адаптеры. Адаптеры не знают о БД. Битый конфиг отключает только свой источник и персистится в `sources.config_error`; preferred его пропускает. Remanga — `sources/remanga/` (JSON API, `external_id` тайтла — `dir`, главы — числовой `id`, `branches`). RuMix — `sources/rumix/` (HTML, `external_id` — slug, главы — `data-id`, поиск POST-формой, `base_url` — origin сайта, UA обязан начинаться с `Mozilla/5.0`, картинки подписаны, 18+ через `?mtr=true`). Mangamir — `sources/mangamir/` (HTML, `external_id` тайтла — slug, главы — `data-chapter-slug`, поиск `GET /manga?q=`, картинки `img.mangamir.com/pages/...`, метаданные из JSON-LD, UA обязан начинаться с `Mozilla/5.0`; свёрнутая страница отдаёт только первые и последние главы, полный список приходит Livewire-вызовом `showAllChapters` с CSRF-токеном и куками того же GET). `chapter_key` строит общий `sources/keys.rs`. Парсеры — чистые функции с фикстурами и `contract_suite`.
- Приоритеты: `source_priorities(lang, source_id, rank)`, ранг 0-based, `lang='*'` — запасной **только если для языка тайтла нет ни одной строки** (наборы не смешиваются). `GET/PUT /api/admin/source-priorities?lang=` заменяет список целиком и пересчитывает preferred у всех тайтлов. **Приоритет важнее полноты**: `recompute_preferred` сортирует effective enabled (`enabled`, `base_url IS NOT NULL`, `config_error IS NULL`) по `rank`, `is_primary`, затем `chapter_count`; `order` для варианта главы ставит известную недоступность (`locked`/`missing`) в конец, затем `rank`, `preferred`, `is_primary`, `ordinal_site`. Поэтому 30 глав с Remanga остаются с Remanga, а главы 31+ приходят из другого источника. Пересчёт также после `save_config`, `update_title(lang)`, detach и attach (заполняет `titles.lang`, если NULL).
- Alias и fallback: `candidates()` включает главы с canonical-ключом **и** alias-варианты, поэтому fallback видит связанную главу другого источника. Пары диапазонов привязаны к `source_entry` (один и тот же `chapter_key` двух источников не перетирается); группировка и `candidates` сначала смотрят пару своего entry, затем глобальную ручную. Цепочки alias запрещены; при отвязке удаляются alias, чей alias-ключ исчез (canonical-only alias сохраняется как стабильный ключ прогресса). `GET /api/titles/{id}` отдаёт `aliases` и raw `chapter_key` варианта; для чтения выбирается первый доступный вариант рабочего источника, а `volume`/`number_text`/`number_milli`/`chapter_kind` группы берутся у варианта, чей собственный ключ равен canonical. Поэтому alias можно исправить неверный том: обе версии станут одной главой с правильной нумерацией, а контент продолжит приходить из приоритетного источника. `POST /api/titles/{id}/chapter-aliases/bulk` (`{ aliases }`, до 500, admin; фронтенд дробит длинные пачки) пишет пачку одной транзакцией, проверяет цепочки после вставки и переносит `progress`/`chapter_reads` с alias-ключа на canonical. Перепривязка существующего alias к другому canonical — 409 `alias_exists`: сначала удалите связь, иначе прогресс остался бы на старом ключе. `is_locked` синхронизируется с availability при mark/успешном refresh страниц.
- Инвариант источников: один `source_entry` на `(title_id, source_id)` (уникальный индекс 0003); повторная привязка другого `external_id` того же источника к тому же тайтлу — 409 `source_already_attached`.
- Админские связи: `POST/DELETE /api/titles/{id}/sources`, `PUT /api/titles/{id}/primary-source` (`{ source_entry_id }`), `GET/POST/DELETE /api/titles/{id}/chapter-aliases`, `POST /api/titles/{id}/chapter-aliases/bulk`, `POST /api/admin/refresh/{title_id}` (per-entry статус, сеть до транзакции; заодно добирает отсутствующие обложки источника — так их получают тайтлы, импортированные до автоскачивания). В UI привязка источника убрана (`AdminSourcePanel` удалён); эндпоинты остаются для API и тестов. `PUT /api/sources/{code}` без `base_url` сохраняет прежний origin; при первом включении фронтенд подставляет `default_base_url` из дескриптора.
- Связки-диапазоны (admin): `GET/POST /api/titles/{id}/alias-ranges`, `PUT/DELETE .../{range_id}`, `POST .../apply` (`{ ranges: [{ source_entry_id, anchor_chapter_id, canonical_chapter_id }] }`). Связка привязана к `source_entry_id` и якорю-главе, действует от якоря до следующей связки этого источника и типа. Точные пары `chapter_aliases` с `origin='range'` и `source_entry_id` — производная: пересобираются после refresh/import, detach и CRUD. Ручные пары (`source_entry_id IS NULL`) не трогаются. Смещение считается из координат якорей; при дрейфе якоря связка получает `needs_review` и не пересчитывается. Если канонической главы ещё нет, пара не создаётся («ожидает»). Старые alias сворачиваются в диапазоны при первом `GET /alias-ranges` (только непрерывные серии с одинаковым смещением). Прогресс/`chapter_reads` переносятся одним проходом; при удалении связки остаются на canonical. Решение — 0012.
- Импорт (внутренний, без отдельного HTTP-маршрута): при добавлении из библиотеки и при привязке источника сервер получает метаданные, определяет тип тайтла из источника и пишет главы upsert в транзакции; `chapter_key` фиксируется при первом импорте, расхождение — в `source_entries.last_error`. Если `title_id` не передан (добавление из библиотеки), `find_title_by_names` ищет существующий тайтл по точному нормализованному названию или alt name и привязывает источник к нему. После импорта считаются статистики и `titles.preferred_source_id`.
- Синхронизация страницы тайтла: `POST /api/titles/{id}/sync` доступен любому пользователю с сессией, под rate limit и внутренним TTL 10 минут (`titles.metadata_synced_at`). Обновляет главы всех entry, пересчитывает preferred, обновляет source-обложки (`refresh_source_covers`, ручные не трогает) и применяет общие метаданные. Метаданные сливаются из всех источников в порядке preferred → rank → привязка: первый непустой `name`/`description`/`status`/`year`/`rating`/`lang`, первый конкретный `kind` (не `other`), списки `alt_names`/`authors`/`genres` объединяются. `titles.source_metadata_json` хранит прошлый снимок: поле, отличающееся от него, считается ручной правкой и не перезаписывается. `GET /api/titles/{id}` по-прежнему читает только БД; фронтенд вызывает sync в фоне и инвалидирует `title`/`library`/`chapter-content`/`progress`.
- Контент главы: `GET /api/titles/{title_id}/chapters/{chapter_key}/content?lang=` выбирает вариант только из источников выбранного языка (неизвестный язык игнорируется, известный без варианта — 404) и делает fallback (`source_locked` 403, `source_not_found` 404, временные — 502/503); известные страницы отдаются из БД без сети. `GET /api/chapters/{id}/content` — прямой вариант. Прогресс: `GET/PUT /api/progress/{title_id}`, alias → canonical, поле позиции проверяется по `content_kind`; `PUT` также пишет `chapter_reads` по каноническому ключу (`read_count` и отметки глав). Ручная отметка глав — `PUT /api/titles/{title_id}/chapters/read` (`{ chapter_keys, read }`), пачкой для «эта и все предыдущие», не меняет прогресс; возвращает полный `read_keys`.
- `SourceError::Redirect` (3xx без следования): RuMix различает платную главу (`/internal/purchase/...` → `Locked`) и запланированную (`NotFound`); остальные 3xx — 502. Общий `get_text` редиректы не выполняет.
- Картинки: `GET /api/pages/{id}/image` и `GET /api/sources/{code}/cover?ref=` (вторая — любому пользователю с сессией для диалога добавления). Кэш `DATA_DIR/cache/images/<aa>/<sha256>` по ключу `(source_entry_id, external chapter id, idx)`, атомарная запись, single-flight, магические байты (JPEG/PNG/WebP/GIF), `ETag`, `nosniff`, `private`. При `401/403/410` до двух перезапросов списка страниц, затем глава помечается `locked`.
- SSRF: общий DNS-резолвер отбрасывает private/loopback/link-local/CGNAT/ULA/IPv4-mapped, редиректы клиентов выключены, allowlist хостов проверяется до запроса. URL источника — только из реестра; `external_id` валидируется. `SSRF_ALLOW_LOOPBACK` включается только интеграционными тестами с локальным сервером.
- Конфиг — из env: `BIND_ADDR` (по умолчанию `127.0.0.1:3000`), `STATIC_DIR` (`dist`), `DATABASE_URL` (`sqlite://data/cion.db`), `DATA_DIR` (`data`), `REGISTRATION_MODE` (`invite|closed`), `PUBLIC_ORIGIN`/`ALLOWED_ORIGINS`, `COOKIE_SECURE`, `TRUSTED_PROXIES`, `ADMIN_USERNAME`/`ADMIN_PASSWORD`, `RUST_LOG`; в dev `.env` читает `dotenvy`, пример — `.env.example`.
- Миграции — `server/migrations/`, `sqlx::migrate!` при старте. `db::run_migrations` выключает внешние ключи на соединении мигратора (SQLx для SQLite оборачивает миграцию в транзакцию, где `PRAGMA foreign_keys` — no-op, а пересборка родителя иначе каскадно удалит детей), после включает их и выполняет `PRAGMA foreign_key_check`. Схема: `users`, `invites`, `sessions`; каталог и пользовательские данные — `sources`, `titles`, `title_covers`, `source_entries`, `chapters`, `chapter_aliases`, `chapter_alias_ranges`, `source_priorities`, `pages`, `chapter_texts`, `library`, `library_tabs`, `progress`, `chapter_reads`; время — unix seconds (INTEGER). `library` пересобирается в 0004 ради нового CHECK (`not_interested`) и `favorite`, в 0006 `favorite` становится статусом, а в 0007 появляется `custom_tab_id`, и `library_tab_items` удаляется. 0008 задаёт типы тайтла (`manga|manhwa|manhua|western_comic|ru_comic|indonesian_comic|other|original`) и убирает `kind` из `source_entries` и `source_priorities`; старые `anime`/`book` переносятся как `other`, а фактический тип импортированных из Remanga тайтлов восстанавливается из `source_entries.raw_json`. 0009 добавляет в `titles` снимок метаданных (`source_metadata_json`, `metadata_source_id`, `metadata_synced_at`); синхронизация использует снимок и время, `metadata_source_id` оставлен в схеме. 0010 добавляет `chapter_alias_ranges` и `chapter_aliases.source_entry_id/origin` с двумя частичными уникальными индексами (entry-специфичные и глобальные ручные пары). 0011 добавляет `users.avatar_updated_at`: путь к файлу детерминированный (`DATA_DIR/avatars/{user_id}.webp`), поэтому путь в БД не нужен. 0012 добавляет `users.avatar_version` — монотонный счётчик для ETag: `avatar_updated_at` обнуляется при удалении, а версия обязана меняться после повторной загрузки.
- Статику отдаёт `ServeDir` с диска; `rust-embed` не используем, иначе правка UI требует пересборки Rust.
- Тесты API — `tower::ServiceExt::oneshot` по `Router` (`server/tests/`); временные каталоги, SQLite и `DATA_DIR` — в тестах, не в проде.
- В production-коде нет `unwrap` / `expect` / `panic!`; причина `unsafe` — в WHY-комментарии.

## Подводные камни

- Сайдбара и экрана каталога больше нет: `/` — библиотека, `/library` редиректит на `/`. Серверный `GET /api/catalog` остался, но UI его не использует.
- Добавление тайтла идёт через `/api/discover/*`: поиск по всем включённым источникам, импорт — при первом добавлении. Импорт полного тайтла — серия запросов и может занять секунды; `add` ограничен по IP.
- Тип тайтла — свойство тайтла, а не источника: `source_entries` и `source_priorities` его не хранят. При импорте тип берётся из метаданных источника (Remanga — `type.name`, RuMix — заголовок, Mangamir — `type[0]` в разметке), неизвестный становится `other`. Смена типа не блокируется привязанными источниками. При синхронизации `kind` берётся у первого источника, который вернул не `other`.
- «Любимое» — обычный статус библиотеки: он взаимоисключающ с «Читаю»/«Прочитано», отдельного поля `favorite` больше нет. «Не интересно» — тоже полноценный статус. Своя закладка — это ещё один статус, один на тайтл: она перекрывает встроенный, а её удаление возвращает сохранённый встроенный статус. Своих закладок не больше трёх, имя уникально.
- Настройки браузера хранят `locale` и `readerWidth` (ширина колонки читалки); старый `sidebarOpen` игнорируется.
- Для dev нужны оба процесса: без `pnpm dev:server` прокси API отвечает ошибкой.
- Первый администратор создаётся только на пустой таблице `users` из `ADMIN_USERNAME`/`ADMIN_PASSWORD`. После bootstrap переменные убери: пароль остаётся в env и больше не нужен.
- `DATABASE_URL` по умолчанию `sqlite://data/cion.db`, `DATA_DIR` — `data`; каталоги создаются сами и в git не попадают. Миграции применяются при каждом старте; `data/covers/` хранит обложки.
- В dev разрешены Origin `http://localhost:1420`/`127.0.0.1:1420` и те же на `:3000`. Release-сборка без `PUBLIC_ORIGIN`/`ALLOWED_ORIGINS` отклоняет все мутации (403) — это fail closed, а не забытая настройка. В проде также `COOKIE_SECURE=true`.
- Rate limit входа хранится в памяти процесса и сбрасывается при перезапуске; для одного self-host инстанса этого достаточно.
- Сервер раздаёт статику из `dist/`: чтобы проверить SPA на `:3000`, сначала выполни `pnpm build`. После пересборки UI сервер перезапускать не нужно.
- `typescript-eslint` требует TypeScript ниже 6.1: не обновляй `typescript` до 7, пока этот диапазон не расширят.
- `Cargo.lock` (в `server/`) и `pnpm-lock.yaml` коммитятся. `node_modules`, `dist`, `server/target`, `data/`, `.env*` (кроме `.env.example`) игнорируются.
- CSP пока не задаётся: это фаза 8 (заголовки сервера или Caddy). Инлайновый скрипт темы уже вынесен в `public/theme.js`, чтобы позже не требовать `'unsafe-inline'`; в dev строгий CSP отключён ради Vite/React Refresh.
- Ключ темы `theme` читают и `public/theme.js`, и `ThemeToggle.tsx`; меняй их вместе.
- Источник включается через `PUT /api/sources/{code}` (`base_url`, `enabled`); строки всех адаптеров уже созданы реестром, а `default_base_url` подставляется фронтендом при первом включении. У Remanga `base_url` — API-хост `https://api.remanga.org`, а не сайт; `dir` тайтла содержит `<...>` и обслуживается только закодированным в пути. У RuMix `base_url` — сайт `https://rumix.me` (не `http://` и не `www`); без UA с префиксом `Mozilla/5.0` сайт отвечает 402, поэтому в конфиге есть `user_agent`. У Mangamir `base_url` — сайт `https://mangamir.com`, картинки — `img.mangamir.com`, UA также обязан начинаться с `Mozilla/5.0`. Импорт полного тайтла — это серия запросов, он может занять секунды.
- RuMix не помечает платные главы в списке: `content()` получает 302 на `/internal/purchase/` и возвращает `source_locked`, после чего fallback идёт в другой источник. На импорте такие главы остаются `unknown` (ленивое определение). Картинки на `*.rumix.me` подписаны и протухают — прокси перезапрашивает `content()` при 401/403/410.
- Mangamir отдаёт все страницы главы прямо в HTML (`img[src*="/pages/"]`) и метаданные в JSON-LD; главы — `li[data-chapter-slug]`, номер/том/название — из `title` ссылки. Список глав на странице свёрнут (первые + последние): адаптер находит Livewire-компонент `pages::book.show` по `wire:snapshot`, берёт `livewireScriptConfig.uri`/`csrf` и `Set-Cookie` того же GET и делает `POST showAllChapters`; только после этого в `effects.islandFragments` приходят все `li[data-chapter-slug]`. Без вызова импортировались бы единицы глав. Если полный список получить не удалось (или страница свёрнута, а компонента нет), `chapters()` возвращает ошибку, а не свёрнутый HTML: иначе sync записал бы усечённый список как успешный. Один источник может отдать только одну обложку или тип, которого нет у Remanga: адаптер приводит тип к `TitleKind`, а синхронизация добирает недостающие размеры обложек и поля из других источников.
- `source_priorities` заменяется целиком: `PUT` с `lang` и `source_codes` в нужном порядке. Ранг в API 0-based. После сохранения preferred пересчитывается, но `is_primary` не меняется. Ручной alias — один hop: canonical не может сам быть alias, alias не может быть canonical другой связи; иначе 409 `alias_chain`. Диапазоны материализуют пары только в корневые canonical-ключи и не пишут цепочки; при конфликте/дрейфе связка уходит в `needs_review`.
- `page` в прогрессе — 0-based индекс `pages.idx`, не человеческий номер страницы. `PUT /api/progress/{title_id}` до первого открытия главы с `content_kind = NULL` вернёт 409 `content_kind_unknown`.
- Тестовый адаптер `fixture` компилируется только в `debug_assertions`; в release его нет. `SSRF_ALLOW_LOOPBACK=true` существует только для тестов с локальным HTTP-сервером.

## Происхождение

Проект начинался как десктопный шаблон `cion-winflow` на Tauri. Теперь это продукт `cion-reader`: фронтенд переехал в веб, Tauri-слой удалён. История осталась в git.
